## §4 — Latent Gaps Discovered

| # | Gap | Severity | Affected component | Remediation |
|---|---|---|---|---|
| L1 | Only **8 of 19** question types have LLM prompts in `llmPrompts.ts`. The 11 missing types: `MULTIPLE_CHOICE_SINGLE_IMAGE`, `YES_NO_NOT_GIVEN`, `TABLE_COMPLETION`, `NOTE_COMPLETION`, `FORM_COMPLETION`, `DIAGRAM_LABEL`, `MAP_LABEL`, `MATCHING_INFORMATION`, `MATCHING_FEATURES`, `MATCHING_ENDINGS`, `DIAGRAM_LABEL` (already covered by MAP?). | **High** — limits auto-gen pilot to 8 types | `langfens-fe-app/src/app/admin/_lib/llmPrompts.ts` | **Sprint 7** — close the prompt coverage gap to 19/19 with same `STRICT_JSON_INSTRUCTION` discipline |
| L2 | `LLM_PROMPTS` schema/example-payload templates may diverge from each other in JSON-shape instructions; needs canonical per-type shape from `questionSchemas.ts` (`jsonShape` field). | Medium | `llmPrompts.ts` | **Sprint 7** — extract per-type `JSON_SHAPE` from `questionSchemas.ts` and have each prompt reference it (avoids drift) |
| L3 | `aiConfig.ts` only supports `anthropic` + `openai` + `google` (gemini). The repo's primary provider is Groq via `ai-service` (Python). FE doesn't talk to `ai-service` directly. | Medium | `aiConfig.ts`, `AiAuthorModal.tsx` | **Sprint 7** — add a `groq` provider + a server-side proxy option through `ai-service` (so secrets stay server-side) |
| L4 | No auto-gen support for **Listening** (needs audio transcript), **Writing** (needs task prompt + chart), or **Speaking** (needs roleplay scenario). Currently only Reading flow exists. | **High** | `AiAuthorModal`, `services/ai-service` | **Sprint 8** — extend auto-gen to all 4 skills |
| L5 | No regression test that the LLM-generated JSON actually deserializes into `AdminQuestionUpsert` after the G13 DTO field additions (`imageUrl`, `modelAnswers`, etc.). | Medium | new Vitest suite | **Sprint 7** — add a fixture-based test in `src/app/admin/_lib/__tests__/llmPrompts.test.ts` |
| L6 | Generated questions are created one-by-one via `createQuestion`. No bulk endpoint for "generate N questions for section X" with single transaction. | Medium | `services/exam-service` admin endpoints | **Sprint 8** — add `POST /api/admin/question/bulk` for atomic insert |
| L7 | `Difficulty` and `Skill` are auto-mapped from `typeMeta.defaultDifficulty` but no validation that LLM-supplied `difficulty` stays in `[1,5]`. | Low | `AiAuthorModal.tsx:72` | **Sprint 7** — clamp at FE side; existing BE D5 validator will reject out-of-range values |

These gaps justify **Sprint 7 (prompt coverage + schema unification)** and **Sprint 8 (multi-skill auto-gen)** as the next two sprints.
