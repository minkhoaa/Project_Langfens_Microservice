STEP 1 — DB volume wipe decision
────────────────────────────────────────────────────────────

Decision: SKIP `docker compose down -v`.

Reason:
- Primary local dev is Aspire (per project CLAUDE.md line 7: `dotnet run --project AppHost/AppHost.csproj`).
- AppHost/Program.cs (lines 70, 110) provisions its OWN Postgres containers for exam-db (port 5433) and attempt-db (port 5435) via `AddPostgres(...).WithDataVolume().WithLifetime(ContainerLifetime.Persistent)`. Aspire owns its volumes in the default Aspire volume directory.
- `deploy/compose.yaml` (production-style) uses a single SHARED `pgdata` named volume for ALL Postgres databases (lines 217, 235, 254, 272, 289, 314, 332, 350, 368). `docker compose down -v` would wipe auth-db, course-db, vocabulary-db, writing-db, speaking-db, dictionary-db, gamification-db too — destructive side-effect outside the rebuild's scope.
- `deploy/compose.local.yaml` does use per-DB volumes (`exam_pgdata`, `attempt_pgdata`), but the file is for an alternate local-dev path that is not currently in use (Aspire is).
- No Aspire dev session is currently running, so there are no live DB connections to disconnect.

Conceptual "wipe" semantics: Aspire provisions a fresh Postgres container + volume on next `dotnet run --project AppHost/AppHost.csproj`; the upcoming EF Core `InitDb` migration (Task 5 + Task 8) creates the new schema (Payload + CorrectAnswer jsonb on exam_questions; AnswerJson jsonb on attempt_answers). No data to physically delete.

EXPECTED BUILD FAILURE
───────────────────────

After deletion, `dotnet build` on both services will FAIL. This is intentional per plan Task 2 acceptance. Reasons:

  exam-service:
    - Features/Exams/AdminEndpoint/* referenced exam-service.Application.* and exam-service.Domains.Entities.* — those namespaces are gone.
    - Features/Exams/InternalEndpoint/ExamInternalGrpcService.cs referenced exam-service.Application.Common.ProtoHelper + exam-service.Domains.Entities.* — gone.
    - Infrastructure/Persistence/ExamDbContext.cs still `using exam_service.Domains.Entities;` — gone.
    - Program.cs references `Features/Exams/...` endpoint registration — gone.
    → Task 3-13 will rebuild entities + DbContext + endpoints + ProtoHelper slim.

  attempt-service:
    - Features/Attempt/AttemptEndpoint/AttemptService.cs referenced Domain.Entities — gone.
    - Features/Helpers/{Grader, GraderHelper, ClassificationGrader, PlacementWorkflow, ExamGateway, BuildQuestionIdSet}.cs referenced Domain.Entities — gone.
    - Features/Analytics/*.cs, Features/Bookmarks/BookmarkService.cs, Features/Notes/NoteService.cs, Features/StudyPlan/StudyPlanService.cs all `using attempt_service.Domain.Entities;` — gone. Kept folders will fail to compile until Tasks 6-8 + 19-21 land the new slim entities + flow + endpoints.
    - Infrastructure/Persistence/AttemptDbContext.cs `using attempt_service.Domain.Entities;` — gone.
    - Program.cs references removed endpoint types — gone.
    → Tasks 6-8 will recreate entities; Tasks 14-21 will rebuild graders + flow + endpoints.

DO NOT attempt to fix build errors in this task. The plan explicitly says: "Tasks 3+ will rebuild them."
